- [x] 3.4 Benchmark the sidebar + Kanban update cost with 500 threads and 10 streaming agents before and after (add the scenario to `packages/client-benchmark` or a vitest bench); verify there is no regression above 10% and record the numbers in the PR
  - Measured (`FUNNY_BENCH=1 … threads-update-cost.test.ts`, 200 frames). Legacy: ≈0.15–0.17 ms/frame. Data layer, unbatched: ≈0.6 ms/frame. After coalescing each realtime rAF flush into one synced commit (`batchWrites`): ≈0.42–0.50 ms/frame (≈3%). Breakdown: writes 0.04 ms, live-query incremental maintenance ≈0.2 ms (the library's floor, with or without the `inArray` filter), Kanban grouping 0.13 ms (same as legacy). Decision (user, phase 3): coalesce writes per flush and close; the 10% criterion is replaced by the absolute budget enforced by the bench (< 16 ms/frame, observed ≈0.5 ms).

  - Done as: `stores/thread-view.ts` merges payload + row (`{ ...payload, ...row }`, memoized per pair; row always wins). The `thread-context` hooks, `useActiveThreadView` / `useThreadViewById` and `readActiveThreadView` / `readThreadView` are the read API. `adoptThreadDetail` gives a URL-opened thread a row without list membership; a held row wins over the (possibly cached) detail. `thread-projection.ts` is deleted; `patchThreadRow` no longer returns an `activeThread` copy.   - Deviation: row fields stay on the `ThreadWithMessages` type. Payload patches that set row fields remain only for rowless payloads (tests, very early events); writers that change row fields also patch the row.
