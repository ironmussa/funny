# Spec Delta

## Purpose

Lets each user choose one model for funny's small helper generations (thread recaps, commit messages), from any supported provider, independent of the models their agents run on.

## ADDED Requirements

### Requirement: Per-user utility model setting

Each user SHALL have a utility model setting made of a provider (`claude-sdk`, `anthropic`, `openai`, `ollama` or `openai-compatible`), a model id, and for `openai-compatible` and `ollama` an optional base URL. When the user has not set it, the utility model SHALL be provider `claude-sdk` with model `haiku`. The setting SHALL be edited in Settings > Profile and SHALL be findable through the settings filter.

#### Scenario: Default for a new user

- **WHEN** a user who never changed the setting triggers a helper generation
- **THEN** it runs on Claude Haiku through the Claude Agent SDK

#### Scenario: User picks an OpenAI model

- **WHEN** a user sets provider `openai` and model `gpt-4o` and saves
- **THEN** their later recaps and commit messages are generated by `gpt-4o`

#### Scenario: Invalid setting is refused

- **WHEN** a user saves provider `openai-compatible` without a base URL
- **THEN** the save is refused with 400 and the previous setting is kept

### Requirement: Helper generations use the utility model

Thread recaps and generated commit messages SHALL run on the requesting user's utility model, on that user's runner, as a single turn with no tools.

#### Scenario: Commit message with a non-default utility model

- **WHEN** a user whose utility model is `ollama` / `llama3` asks for a generated commit message
- **THEN** the message is generated by that Ollama model on their runner

### Requirement: Utility model credentials

An LLM API utility model SHALL use the user's own provider key for that provider, the same key LLM API agent threads use, and the key SHALL never be returned to the browser. When no credential is available for the chosen provider, the generation SHALL fail with a distinct `utility-model-unavailable` error naming the provider, and the caller SHALL NOT fall back to another provider or another user's credentials.

#### Scenario: Missing OpenAI key

- **WHEN** the utility model is `openai` and the user has no OpenAI key saved
- **THEN** the generation fails with `utility-model-unavailable` for provider `openai`, and no other provider is tried
